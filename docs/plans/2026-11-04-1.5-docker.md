# 2026-11-04 — 1.5: Docker (imagen de ingesta + `docker compose run ingest`)

## Contexto
El comando `sintesis-ingest` (1.4) corre en tu máquina porque ahí están instalados uv, Python 3.13 y las
dependencias. Docker empaqueta todo eso en una **imagen**: una "caja" que corre igual en cualquier computador y en la
nube. Es lo que Cloud Run ejecutará en la fase 4. Con esta tarea se cumple el "listo cuando" de la fase 1: con
Docker, una corrida baja la UF y el IMACEC, deja el raw y los CSV en `./data`, y una segunda corrida no duplica nada.

## Requisito previo (Rafael)
Docker Desktop está instalado en Windows, pero no conectado a WSL. Hay que abrir Docker Desktop → **Settings →
Resources → WSL integration** → activar la distro **Ubuntu** → *Apply & restart*. Después, `! docker version` debe
responder.

## Rama
`feat/1.5-docker`, desde `main`.

## La idea en simple
```
Etapa 1 "taller" (imagen con uv):  instala las dependencias exactas de uv.lock en /app/.venv
Etapa 2 "caja final" (python slim): copia solo el .venv y el paquete. Sin uv, sin tests, sin .env
                                     corre como usuario sin privilegios; orden por defecto: sintesis-ingest
docker compose run --rm ingest run --source bcentral_uf
   → credenciales: entran como variables desde tu .env al correr (nunca dentro de la imagen)
   → datos: ./data de tu máquina se monta en /app/data (los archivos quedan donde ya están)
```

## Decisiones (con su porqué)
| Decisión | Por qué |
|---|---|
| **Multi-stage**: `ghcr.io/astral-sh/uv:0.12.23` (taller) + `python:3.13-slim` (final), versiones fijas | La caja final no lleva herramientas de construcción: es más chica y tiene menos superficie de ataque. Las versiones fijas hacen que la imagen sea reproducible (las mismas que usas en local) |
| `uv sync --frozen --no-dev --package sintesis-ingest` | Instala exactamente lo de `uv.lock`, sin pytest ni ruff |
| **Usuario sin privilegios** (`appuser`, uid 10001) | Si algo se compromete dentro del contenedor, no es root. Lo pide el plan (§5, fase 1) |
| **`.dockerignore` estricto**: `.env*` (salvo `.env.example`), `data/`, `.git/`, `.venv/`, `docs/`, tests | Lo que no entra al contexto de construcción no puede terminar en la imagen. Primera barrera para que tus credenciales nunca queden "horneadas" |
| **Credenciales por `env_file: .env` en compose**, al correr | Igual que en Cloud Run (variables de entorno desde Secret Manager): el mismo código, sin `.env` dentro de la imagen. Aviso: `docker inspect` del contenedor muestra las variables; es aceptable en local y en la nube lo resuelve Secret Manager |
| **`./data` montada en `/app/data`** y `user: ${UID}:${GID}` en compose | Los archivos quedan en tu carpeta y son tuyos (si no, los escribiría el uid 10001 y no podrías borrarlos sin `sudo`). La imagen sigue siendo no-root por defecto |
| `ENTRYPOINT ["sintesis-ingest"]` | `docker compose run ingest run --source X` es la misma orden que en local |
| Makefile: `docker-build` y `docker-run SOURCE=<id>` | Atajos, como `run-local` |
