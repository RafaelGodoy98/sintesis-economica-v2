# 2026-10-30 — 0.5: tooling Python (uv, ruff, pytest, pre-commit) + permisos de Claude

## Contexto
Antes de escribir código de ingesta (0.6 en adelante) necesitamos tres cosas: dependencias reproducibles,
un lint y un formato que no dependan de quién edita, y tests que corran con un solo comando.
El criterio de "listo" de la fase 0 es: `make test` pasa en una máquina limpia y `pre-commit run --all-files` no reclama nada.
Además se suman los deny/ask de `.claude/settings.json` acordados en la 0.4.

## Decisiones (con su porqué)
| Decisión | Por qué |
|---|---|
| **uv workspace en la raíz**: `pyproject.toml` raíz (virtual, sin paquete) con `members = ["ingest"]` y grupo `dev` (ruff, pytest, pre-commit, detect-secrets) | Un `uv.lock` y un `.venv` para todo el repo. Las herramientas de desarrollo son del repo, no del paquete `ingest`, que solo lleva lo que necesita en producción (su imagen Docker queda liviana) |
| **dbt fuera del workspace** (`transform/` tendrá su propio entorno en la fase 3) | dbt arrastra muchas dependencias y suele chocar con versiones de otras librerías. Mantenerlo aparte evita que un upgrade de dbt rompa la ingesta |
| **Python 3.13** (`requires-python = ">=3.13,<3.14"`, `.python-version`) | Ya está instalado vía uv y es estable. 3.14 es muy reciente para el ecosistema de GCP. Se fija una versión menor para que local, Docker y CI sean iguales |
| **`ingest/` con src layout** (`ingest/src/sintesis_ingest/__init__.py`, `ingest/tests/`) | La estructura de `docs/plan.md` §4. El src layout obliga a testear el paquete instalado y no los archivos sueltos, lo que evita tests que pasan por accidente |
| **ruff**: config en el `pyproject.toml` raíz. `line-length = 110`. Reglas: `E, F, W, I, B, UP, SIM, S` (S = seguridad: detecta, p. ej., `requests` sin timeout) y `S101` permitido en tests | Una sola config para todo el repo. Es lint más formato (reemplaza black, isort y flake8) |
| **pre-commit** (única fuente de verdad del lint, plan §7.2): ruff (check `--fix`), ruff-format, detect-secrets con `.secrets.baseline`, y del repo pre-commit-hooks: `end-of-file-fixer`, `trailing-whitespace`, `check-yaml`, `check-toml`, `check-added-large-files` (500 KB), `check-merge-conflict` | Lo mismo que correrá la CI en la fase 5. detect-secrets bloquea commits con claves. El límite de tamaño evita subir los 51 MB del INE por error (0.8). sqlfluff y `terraform fmt` se agregan cuando exista SQL o Terraform |
| **Versiones de los hooks fijadas** (`rev:` exacto, obtenido con `pre-commit autoupdate` al crearlo) | Reproducibilidad: el mismo commit produce el mismo resultado de lint en cualquier máquina |
| **Makefile**: `setup` (`uv sync` + `pre-commit install`), `test` (`uv run pytest`), `lint` (`uv run pre-commit run --all-files`), `help` | Los comandos que ya anuncia CLAUDE.md. `run-local` y `dbt-build` se agregan cuando existan |
| **Test de humo**: `ingest/tests/test_package.py` verifica que `sintesis_ingest` se importa y expone `__version__` | `make test` necesita al menos un test real. Este prueba que el empaquetado funciona |
