# 2026-11-03 — 1.1a: secretos locales (.env, hook, lectura desde el programa)

## Contexto
Rafael creó `.env` con las credenciales BDE. Antes de que el código las use (1.3), cerramos las vías de filtración
con mejor relación costo/beneficio. Decisión de Rafael: **forma B**: el programa lee el `.env` por su cuenta y nada se
exporta en la terminal (así tampoco quedan en el entorno de Claude).

Hallazgos de la documentación de Claude Code (subagente `web-fetch`):
- **Las reglas `Read(...)` no frenan cualquier comando:** cubren la herramienta Read y comandos como `cat`/`head`/`sed`, pero no `grep -r` ni subprocesos arbitrarios. Eso solo lo bloquea el sandbox, a nivel del sistema operativo.
- **La ruta recomendada para el proyecto es `Read(./.env)`, `Read(./.env.*)`.** Un `//**` antes del primer directorio no funciona en el sandbox de Linux.

## Incidente durante el spike de la 1.1 (2026-11-03)
- Un script de exploración (fuera del repo) usaba pydantic-settings con `SecretStr`. Al faltar `SINTESIS_CONTACT_EMAIL`,
  el `ValidationError` de pydantic **imprimió los valores de entrada, incluida la clave BDE**, que quedó en el historial
  de la conversación. `SecretStr` no protege cuando la validación falla.
- Acción de Rafael: rotar la clave BDE.
- Corrección: `Settings` usa `hide_input_in_errors=True`. Test nuevo: un error de configuración no muestra valores
  (se comprobó que el test falla si se quita la protección).
- Hallazgos de la API (para la ficha): responde **HTTP 200 incluso con credenciales inválidas** (`Codigo=-5`,
  "Invalid username or password"); el parámetro `user` es el **email** registrado.
