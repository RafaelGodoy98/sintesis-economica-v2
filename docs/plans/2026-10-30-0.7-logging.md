# 2026-10-30 — 0.7: logging estructurado en JSON

## Contexto
El pipeline correrá sin nadie mirando la consola (Cloud Run Jobs, fase 4). Cuando algo falle habrá que responder rápido
"¿qué corrida, qué fuente, qué pasó?". Para eso cada línea de log debe ser JSON con campos fijos, que Cloud Logging
indexa y permite filtrar (p. ej. `jsonPayload.source_id="senado_leyes_publicadas" AND severity>=WARNING`).
V1 usaba `print("[OK] ...")`: legible para una persona, pero no filtrable.
Listo cuando: hay un test que verifica el formato (plan §7.5).

## Rama
`feat/0.7-logging`, desde `main`.

## Decisiones (con su porqué)
| Decisión | Por qué |
|---|---|
| **`logging` de la librería estándar + un formateador JSON propio** (~60 líneas) | Sin dependencias nuevas, y todas las librerías (google-cloud, requests) ya escriben con `logging`, así que sus mensajes salen en el mismo formato. Alternativas: `structlog` o `python-json-logger`, que son útiles pero agregan una pieza más por aprender para algo que se resuelve en pocas líneas |
| **Una línea JSON por evento, a stdout** | Cloud Run envía stdout a Cloud Logging y reconoce cada línea JSON como un log estructurado |
| **Campos**: `timestamp` (UTC, ISO 8601), `severity`, `message`, `logger`, `run_id`, `source_id` y los extras que se pasen | `severity` y `message` son los nombres que Cloud Logging interpreta como nivel y texto: con otro nombre, todo aparecería como DEFAULT |
| **`run_id` y `source_id` por contexto** (`contextvars` + un context manager `log_context(run_id=..., source_id=...)`) | Se fijan una vez al inicio de la corrida o de la fuente y aparecen en todas las líneas, incluidas las de librerías. No hay que pasarlos en cada llamada, ni existe el riesgo de olvidarlos |
| **`new_run_id()`**: UUID4 en hex | Único por corrida. En la fase 4 se puede reemplazar por el id de ejecución de Cloud Run |
| **Excepciones en el campo `exception`** (traceback como texto) dentro de la misma línea JSON | Un traceback impreso suelto se parte en muchas líneas y pierde el `run_id` |
| **Redacción de secretos en el formateador**: en cualquier texto, los parámetros de URL `user`, `pass`, `password`, `token`, `key`, `secret` y `apikey` quedan como `***` | CLAUDE.md: la API BDE pasa usuario y clave en la URL. Es defensa en profundidad: el cliente HTTP de la fase 1 tampoco debe loguear URLs completas, pero si una se cuela (p. ej. en el mensaje de una excepción de `requests`), no llega a los logs |
| **Módulo `sintesis_ingest/log.py`**, con `configure_logging(level)` que usa `Settings.log_level` | El nombre `logging.py` taparía al módulo estándar. La función es idempotente: llamarla dos veces no duplica las líneas |

## Convención de niveles (acordada al cierre)
Regla práctica: ¿alguien tiene que hacer algo? No → INFO · quizás, revisar → WARNING · sí, falta un dato → ERROR.
| Nivel | Cuándo | Ejemplo |
|---|---|---|
| DEBUG | Detalle para desarrollar; apagado en la nube | cadena de consulta armada |
| INFO | Hitos normales | inicio de corrida, descarga lista, guardado en raw |
| WARNING | Inesperado, pero la corrida siguió; resultado posiblemente incompleto | 0 filas, tope de 1.000 filas, reintento |
| ERROR | La fuente falló y su dato no se guardó; las demás siguen | sin respuesta tras 3 intentos, el parser no encuentra la tabla |
| CRITICAL | La corrida completa no puede continuar | falta `SINTESIS_CONTACT_EMAIL`, sin acceso al bucket |
Las alertas de la fase 4 se configurarán desde ERROR hacia arriba.

Formato: JSON Lines (un objeto JSON por línea) con los campos especiales de *structured logging* de Cloud Logging (`severity`, `message`).

## Resultado de la verificación
- `make test`: 24 passed (11 nuevos). `make lint` limpio.
- Falla inicial: 7 tests sin salida. Causa: el fixture configuraba el handler durante la preparación del test, y pytest cambia `sys.stdout` entre la preparación y la ejecución. Solución: `configure_logging(level, stream=None)`; los tests escriben a un buffer en memoria (por defecto sigue siendo stdout).
- Salida real revisada: `run_id` en toda la corrida, `source_id` solo dentro de la fuente, usuario y clave de una URL redactados como `***`.
- Nada llama aún a `configure_logging()`: lo hará el CLI en la fase 1.
